Déploiement de Flexisip sur Debian 12 et Configuration pfSense

Par : YANG Liam - SIO

Qu'est-ce que Flexisip (Linphone) ?

Flexisip est une suite logicielle de serveur SIP développée par Belledonne Communications, l'entreprise derrière la célèbre application de softphone Linphone. Conçu pour être hautement évolutif et modulaire, Flexisip gère le routage des appels SIP, l'enregistrement des utilisateurs (Registrar) et l'envoi de notifications push pour les applications mobiles. Il est idéal pour déployer une infrastructure de Voix sur IP (VoIP) sécurisée et performante.

I Résumé de la documentation

Ce projet détaille la mise en place d'une infrastructure réseau de base avec pfSense et le déploiement d'un serveur SIP Flexisip sur un environnement Linux.

1. Configuration pfSense

La première étape consiste à configurer le routeur pfSense. Cela inclut le paramétrage de l'interface WAN avec une adresse IP statique, suivi de la configuration de l'interface LAN pour attribuer l'adresse IP du routeur côté réseau local.

2. Préparation Debian 12

Avant d'installer le serveur SIP, le système Debian 12 "Bookworm" doit être préparé. Cela nécessite l'ajout du dépôt officiel Belledonne et de sa clé de sécurité GPG . Les dépendances de base de données, comme libmariadb-dev, sont également installées.

II Installation et Paramétrage de Flexisip

Installation des paquets

  • Installation du paquet principal bc-flexisip via le gestionnaire APT.
  • Démarrage des services flexisip-proxy et flexisip-presence via systemctl.
  • Vérification de la version installée (2.4.3-1) à l'aide de la commande dpkg -s flexisip.

Configuration du fichier flexisip.conf

Le fichier de configuration principal est par défaut pas configuré, il faut donc le configurer à la main:

  • Transports : Écoute sur tous les protocoles SIP standards (transports=sip*).
  • Sécurité : Activation du module DosProtection pour contrer les attaques par déni de service.
  • Authentification : Désactivée pour permettre les requêtes sans mot de passe lors de cette phase.
  • Registrar : Activé pour tous les domaines avec une expiration fixée à 7 jours (604800 secondes).
  • Routeur : Activation du late forking pour conserver et délivrer les messages aux utilisateurs hors-ligne à leur reconnexion.
